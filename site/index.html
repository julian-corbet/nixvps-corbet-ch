nixvps

NixOS profiles for tiny cloud VMs

Hardened, memory-disciplined NixOS base profiles for the 1 GB-RAM class of cloud instances — the walls almost everyone running NixOS on a free-tier VPS hits eventually.

Not usable yet

This is a scaffold, not a working project. There is no released module, no example configuration, and nothing here has been tested outside its original context yet.

These patterns were developed and used for real inside a private fleet configuration. Pulling them out into a general-purpose, documented project is in progress.

Scope

RAM-class system defaults

Conservative service defaults and a clamped nix-daemon (build parallelism, cores, memory ceilings) sized for boxes in the ~1 GB class, so a routine rebuild doesn't compete the box's own workload out of memory.

Disk-image baking

Patterns for building a prebuilt disk image (systemd-repart / disko-style partitioning) so a VM boots from a ready image instead of running a full NixOS install step on first boot.

Pull-based self-update

For boxes a central deploy pipeline can't always reach: the node fetches a signed pointer to the next closure, switches to it, and rolls back to the last-known-good generation on a failed local health check.

Explicitly out of scope

Deep zram / zswap / OOM tuning

Memory-pressure engineering below the system-shape layer belongs to the sibling nixram project. nixvps assumes something like it already handles that layer.
